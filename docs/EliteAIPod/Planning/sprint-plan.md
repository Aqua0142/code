## Risks

- **[MEDIUM]** The medication fields beyond name and stock_level (NDC, strength, form, manufacturer) are undefined in the open questions. If the schema is built without these and they are required later, a migration will be needed mid-sprint or post-delivery.
  - _Mitigation:_ At sprint kickoff, resolve the open question about required medication fields before T-001 is executed. Include placeholder nullable columns for likely fields (NDC, strength, form) to reduce future migration risk.
- **[HIGH]** No user-level authentication exists; the application relies entirely on network/infrastructure controls. If the internal network boundary is misconfigured or a device is compromised, ePHI in the medication database is exposed.
  - _Mitigation:_ Confirm with stakeholders that network-level controls (firewall rules, VPN, VLAN isolation) are in place before go-live. Document the assumed security boundary explicitly. Ensure TLS 1.2+ is enforced at the server layer and database encryption-at-rest is validated before deployment.
- **[MEDIUM]** Sub-500ms search latency NFR may be at risk if the database query plan is not optimized, particularly if the schema or index design in T-001 is not validated against realistic data volumes.
  - _Mitigation:_ Seed the database with a representative dataset (~1,000 records) during development. Validate query execution plans and index usage for the ILIKE search pattern. Add a performance assertion to the API layer.
- **[LOW]** WCAG 2.1 AA compliance is a medium-priority NFR but spans multiple frontend tasks (T-003, T-004, T-005). Accessibility issues discovered late in the sprint could require rework across all components.
  - _Mitigation:_ Incorporate accessibility requirements (aria attributes, color contrast, focus management) into the acceptance criteria for each frontend task rather than treating them as a post-implementation audit. Use an automated accessibility linter during development.
