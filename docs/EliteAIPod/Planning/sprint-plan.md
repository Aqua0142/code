## Risks

- **[HIGH]** Fuzzy/trigram search matching (US-001 acceptance criteria) may require a database extension (e.g., pg_trgm for PostgreSQL) that is not available or enabled in the target environment. If the database vendor does not support it, an application-level fallback must be implemented, increasing complexity.
  - _Mitigation:_ Confirm database vendor and available extensions during Sprint 1 task T-001. If pg_trgm or equivalent is unavailable, implement application-level Levenshtein distance matching as a fallback. Document the chosen approach in the API design.
- **[HIGH]** The 200ms end-to-end search latency NFR (including network round-trip, DB query, and UI render) is tight. Without proper database indexing and query optimization, this target may not be met, especially with 5,000 medication SKUs.
  - _Mitigation:_ Create appropriate full-text search indexes (GIN/GiST for trigram, or FULLTEXT) during schema creation in T-001. Implement debounce in T-006 to reduce query frequency. Conduct latency testing against a seeded dataset of 5,000 records before Sprint 2 completion.
- **[CRITICAL]** SQL injection risk is elevated because the search endpoint accepts free-text user input that is used in database queries. Failure to use parameterized queries would expose the pharmacy's medication inventory data.
  - _Mitigation:_ Mandate use of parameterized queries or ORM-level query building in T-002. Include SQL injection test cases in the acceptance criteria review at the Sprint 1 gate. No raw string interpolation into SQL is permitted.
- **[MEDIUM]** WCAG 2.1 AA compliance for low-stock color indicators (US-004) and keyboard focus styles (US-008) may be overlooked if color contrast ratios are not validated. Using color alone to convey status fails WCAG 1.4.1.
  - _Mitigation:_ Task T-007 explicitly requires supplementing color with icons or text labels. Task T-010 requires visible focus indicators. Validate contrast ratios using automated tools (e.g., axe, Lighthouse) during Sprint 2 review gate.
- **[MEDIUM]** The project assumption states the SQL database schema will be 'provided and populated,' but if the actual database is not available at the start of Sprint 1, tasks T-002 and T-005 will be blocked.
  - _Mitigation:_ Confirm database availability and connection credentials before Sprint 1 begins. If the production database is delayed, use a seeded local development database with representative data (5,000 medication records) as a stand-in.
- **[HIGH]** TLS 1.2+ encryption is a critical NFR but is an infrastructure/deployment concern. If the hosting environment is not configured for TLS before the application is deployed, the security requirement will not be met at delivery.
  - _Mitigation:_ Ensure TLS configuration is addressed in the deployment/infrastructure setup (handled outside sprint tasks by devops stage). Verify TLS is active before any user acceptance testing. Include TLS verification as a deployment gate criterion.
