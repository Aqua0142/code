## Components

- **AppHeader**: Top navigation bar displaying the application title and pharmacy context.- **SearchBar**: Text input field for medication search with a search icon and accessible label. Handles local state before debouncing.- **SearchResultsList**: Container for the search results. Manages the display of MedicationResultCard items or StateMessage based on the query status.- **MedicationResultCard**: Displays individual medication details including name and stock level.- **StateMessage**: Reusable component for displaying loading spinners, empty states, and error messages with appropriate icons and aria-live attributes.
## User Flows

### Real-Time Medication Search (Happy Path) _(happy path)_
1. **SearchPage**: Pharmacist types 'met' into the SearchBar → Local state updates immediately. After 300ms debounce, API call is triggered. _(Query length is >= 3, so search executes.)_2. **SearchPage**: System waits for API response → SearchResultsList renders StateMessage (type='loading') _(aria-live region announces 'Loading results'.)_3. **SearchPage**: API returns results → SearchResultsList renders a list of MedicationResultCard components _(Cards display medication name and stock level.)_

### Empty State Search
1. **SearchPage**: Pharmacist types 'xyz' into the SearchBar → API call triggered after debounce. _(Query length >= 3.)_2. **SearchPage**: API returns empty array → SearchResultsList renders StateMessage (type='empty', message='No medications found') _(aria-live region announces 'No medications found'.)_

### Backend Error State
1. **SearchPage**: Pharmacist types 'asp' into the SearchBar → API call triggered after debounce.2. **SearchPage**: API returns 500 or network times out → SearchResultsList renders StateMessage (type='error', message='Unable to reach medication database. Please try again.') _(Error message is announced to screen readers.)_
